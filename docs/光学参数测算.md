## 二、证据分级（重要，别混用）

**A. 本机实测（脚本跑出来的）**
- 27 张 BMP 文件头：25 张 9344×7000、2 张 4024×3036，均为 8 bpp 灰度、像素偏移 1078、标准灰阶调色板、无压缩。
  `65409078 = 1078 + 9344×7000`，与文件大小精确吻合。
- `testimgs/` 中 11 张亮场图，用 `minAreaRect` 拟合 DMD 有效区旋转矩形；取宽高比严格等于 16:9 的 5 张子集，
  得 W = 6497.2 px、H = 3653.2 px，图像倾斜约 0.39°。
- 对亮区内部 1200×1200 ROI 去背景后做 FFT：列/行方向主周期均为 **3.37~3.41 px**，与 s = 3.384 独立吻合。
  说明相机确实分辨出了单个微镜栅格，不是靠 1920 这个数硬除出来的。
- OCR 铭牌照片可读到 `DLP9500BFLN`、`3460135`、`3AZ6N9A 060805E`、`S52` 等字样。

**B. 官方手册（外部查证）**
- TI `DLP9500` datasheet：0.95 inch 对角线、1920×1080 微镜阵列、**10.8 μm 微镜间距**、±12° 翻转角。
- Gpixel `GMAX3265`：9344×7000、**3.2 μm** 像元、29.9×22.4 mm 靶面、全局快门、Mono8/10/12。
  自洽校验：9344×3.2 μm = 29.90 mm，7000×3.2 μm = 22.40 mm。

**C. 推断（未直证）**
- 相机整机型号：SDK 用 `MvCameraControl`（海康）、文件名为海康 MVS 典型命名 `Image_YYYYMMDDHHMMSSmmm.bmp`、
  注释「6500w 像素」、分辨率 9344×7000 —— 四条同时指向 MV-CH650-90。**代码里没有任何型号字符串**。
- 1:1 镜头：由 β = 1.0025 反推，未查镜头实物铭牌。

## 三、测算过程

```
DMD 有效面（物面）   W_dmd = 1920 × 10.8 μm = 20.7360 mm
                     H_dmd = 1080 × 10.8 μm = 11.6640 mm

DMD 像（sensor 面）  W_img = 6497.2 px × 3.2 μm = 20.7910 mm
                     H_img = 3653.2 px × 3.2 μm = 11.6903 mm

β_x = 20.7910 / 20.7360 = 1.0027
β_y = 11.6903 / 11.6640 = 1.0023
β   ≈ 1.00 ×

等价形式：β = p · s / d = 3.2 × 3.384 / 10.8 = 1.0027
其中 s = W_img / 1920 = 3.384 像素/微镜
```

两个方向偏差 0.04%，绝对偏差 0.25% 来自轮廓阈值与倾斜拟合。1:1 是机器视觉标准倍率，结果不是凑出来的。

## 四、对现有工程的影响（要改的地方）

1. **UI 的 `Mirror Size` 默认值 5.4 μm 是错的，差整整一倍。**
   `mainwindow.cpp:969-977` 写着 `setValue(5.4)`，那是 0.47″ DLP4710 的微镜间距；
   本机是 0.95″ DLP9500，应为 **10.8 μm**。该字段标着 `Reserved` 且从未被读取，所以暂时没造成事故；
   但一旦接进物理换算，倍率会算成 2.00×，所有 mm 级结果翻倍。**先改值，再谈启用。**
   自洽校验：算得对角线 23.79 mm = 0.937″，与标称 0.95″ 差 1.4%（标称含封装边框），量级正确。

2. **s = 3.384 正好卡在算法下限上，检测很脆。**
   新算法 `SelectShape(width/height >= 3)` 会滤掉小于 3 px 的连通域。单个微镜像只有 3.38 px，
   一个单微镜坏点成像后约 3~4 px，只留 0.38 px 余量。曝光波动、轻微离焦、倾斜都会让它掉到 3 以下被误杀。
   建议把下限降到 2，或提高倍率到 1.5×（s ≈ 5.1 px）留足余量。

3. **旧算法 `hv_offset = 0.73` 的来源找到了。**
   s 不是整数（3.384），网格步长 `Width/Num + 0.73` 是在硬补累积相位。
   但固定 offset 无法补偿按比例增长的误差，1920 列会漂出上千像素 —— 注释与实现自相矛盾的判断成立。

4. **HDevelop 原型与 C++ 版参数不一致**（`defect_inspection.hdev` vs `Algorithm/dmd_defect_detection.cpp`）：
   `scale_image_range` 200–255 → 100–150；暗区阈值 0–25 → 0–100；`minArea` 9 → 默认 4；
   `GrayThreshold` 130 → 128。切版本时结果不可直接对比，做回归前要统一。

5. **判级硬编码 336/672 仍绑死 1080 行**，与本次光学标定无关，但改 DMD 分辨率时会失效。

## 五、未验证 / 风险

- 镜头实物倍率铭牌、是否加转接环/倍率镜：**未验证**。
- 相机是否开启 binning 或数字缩放：**未验证**。若 9344×7000 是 binning 后的输出，
  有效像元就不是 3.2 μm，β 会按比例改变。这是本结论最大的单点风险。
- 相机整机型号标签：**未验证**，OCR 目录拍的是 DMD 芯片铭牌，不是相机铭牌。
- 0.95″ 标称与实际 0.937″ 差异：来自标称取整/边框，不影响结论。
- 4024×3036 的两张早期图来自另一台相机（12.2 MP），未纳入倍率测算。
- `ocr/ocr.7z`（154 MB）与棋盘格标定图未参与本次测算。目录里有棋盘格/点阵标定图，
  若要相机内参与畸变，可另做一次标定 —— 但**倍率不需要它**，本次是纯几何尺度链。
